# SoL Shuttle

A PWA that replaces the apartment's Samsara share page. It answers "when should I leave for the bus?", plans each person's class day around the bus (which bus makes the first class, every walk, the bus home), and pushes alerts to their phone. It began as Alyan's own tool and went multi-user on 2026-11-16: people sign in with Google and each has their own classes, settings and alerts. Design brief: `PRODUCT.md`. Public repo: github.com/alyan06/sol-shuttle.

## Run

```bash
npm run dev         # http://localhost:3240 on local file storage (.data/). Nobody signs in: everyone is one local person. Preview name "sol-shuttle".
npm run dev:locked  # same, with sign-in on and the passcode "letmein". Preview name "sol-shuttle-locked".
npm run dev:replay  # plays the recorded Friday trip as if live (it includes a detour), for working on the map when the bus isn't running. Preview name "sol-shuttle-replay".
npm run dev:hosted  # against the hosted database: live settings, real alerts. Rarely what you want.
npm test            # planner, timetable, history, alerts, tracking and answer logic
npm run tick:local  # runs the alert check every 30s against the dev server (needs TICK_SECRET as a bearer)
```

## How it fits together

- `lib/samsara.ts` reads the share link's `FleetViewer` GraphQL call: anonymous CSRF + cookie, then a position-only query. The browser can't call it (no CORS), so `/api/shuttle` proxies it with a 14s cache.
- `lib/route.json` is the learned loop: path, typical time per point, stops. Regenerate it with `node scripts/learn-route.mjs --write`, which reads `route-data/*.jsonl` and prints held-out accuracy. Record more with `npm run record -- <minutes>` (reads the share token from `.env.local`). Stops are hand-confirmed in `route-data/stops.json` (`heading` picks the pass on two-way streets, `holdM` covers a wait further on, `leadM` one that starts before the stop). The script prints pauses to help, but pauses alone can't tell a stop from a red light.
- `lib/track.ts` places a ping on the loop. Heading picks the side of two-way streets. A stopped bus reports heading 0, so the way it was last driving (`Course`, kept in `tracking.course` and built by `courseAfter` in `lib/snapshot.ts`) does that job, and the last position decides the rest. The course only counts while the bus is within 150 m of where it was last seen moving, and never inside a stop's zone, where the bus turns around. ETA = typical time difference around the loop.
- `lib/answer.ts` turns that into the headline. `lib/alerts.ts` is the pure alert state machine. `lib/tick.ts` runs one check: it reads the feed once, logs the bus, then runs `userTick` (`lib/user-tick.ts`, pure) for every account and sends web push. The bus's memory is worked out once, for nobody in particular; each person's share only reads it.
- **Accounts.** `lib/auth.ts` + `lib/session.ts`: Google sign-in done by hand (authorisation-code flow, state and nonce in a signed 10-minute cookie, ID-token claims checked), then the app's own signed, HttpOnly session cookie. No auth library and no Supabase Auth, so mauqa's own users are untouched. Ids are `g_<google subject>`, `owner` (the passcode account from the single-user days) and `local` (development). The passcode only signs in while Google isn't configured. `JOIN_CODE`, when set, is owed once by each new account. Every write route checks `sameOrigin`.
- **Storage.** `lib/store.ts`: `shuttle_kv` holds what everyone shares (`tracking` = the bus's memory, `history`); `shuttle_users` holds one row per person with `settings`, `schedule` and `state` in separate columns, so the app (which writes the first two) and the tick (which writes the third) never overwrite each other. Locally it's `.data/*.json` and `.data/users/<id>.json`.
- **Everything a browser sends is cleaned in `lib/validate.ts`** before it's stored, because one malformed schedule would otherwise be read by the tick for everybody. Push endpoints are held to the real push services' hosts: the server posts to them, so anything else would let an account aim the server at an address of its choosing.
- **Bus history → timetable.** Each tick, `lib/history.ts` logs the day (first and last movement, every stop arrival and departure) into `tracking.today`; at midnight it's filed into the `history` row (8 weeks kept). `lib/timetable.ts` turns same-weekday days into recurring runs, first and last bus, and "does it run at all". It promises nothing below two days of a weekday.
- **Schedule.** A flat list of blocks (`ClassBlock`), each with its own days, times, building and optional last day. `kind: 'visit'` is time on campus that isn't a class (library, a job): same bus there, bus home and alerts. Buildings come from ASU's own campus map (`lib/buildings.json`, 203 Tempe buildings, rebuilt by `node scripts/build-buildings.mjs`), picked from a searchable list, never typed. `normalizeSchedule` upgrades older saves on every read (day patterns become per-class days, the gym plan is dropped), so stored rows never need rewriting by hand.
- **The gym was removed on 2026-11-16** at Alyan's request when the app went multi-user: it was his routine, not a feature. Don't bring it back unasked. Someone who wants it adds "other time on campus".
- **Day planner.** `lib/plan.ts` is pure: `planDay` takes the schedule, today's choices, the live bus and the timetable and returns legs (bus, walk, class). Bus times come from the live position for the next loop or so, then the timetable, then the loop length repeated with growing doubt; beyond that the leg says "no time yet" and gives the walking deadline. `advanceProgress` commits to a bus the moment its leave time passes (so the plan doesn't jump to the next bus while he's walking to the stop), and that commit is what sends the leave alert, once per leg. `lib/schedule.ts` holds the two fixed places (SoL, Gammage) and walk estimates.
- **The ride home is watched class by class** (`plan.homeWatch`, `busHomeAlerts`). From 15 min before a class ends, the ride home is measured from that class's building. If a next class follows, only a bus he could leave for before it counts, and the watch goes quiet when that class starts, then moves to it. After the last class every bus is announced (about 10 min before the moment to go) until he taps "I'm on the bus" or "I'm home" (`override.onBusAt` / `homeAt`), or the alert window closes an hour after that class. Nothing is assumed, least of all that they left. The first ride home (leg `back`) is therefore never auto-committed. `override.outEarly` ends a class early. `headsUpAlerts` warns 8 to 25 min before it's time to leave home.
- **Alerts only around time on campus.** `plan.alertWindow` runs from 2 hours before the first class being taken to 1 hour after whatever ends last, unless the person sets their own (`prefs.alertsBeforeMin` / `alertsAfterMin`, defaults `ALERTS_BEFORE_MIN` / `ALERTS_AFTER_MIN`). `withinAlertWindow` drops every push outside it, including first-bus and not-running; a watch started by hand still gets its leave and arrival alerts. Days with no classes are silent. The alert state still updates outside the window, so nothing fires late when it opens. With no classes set up at all, nothing is filtered.
- **No location.** Live location was tried for one evening and dropped at Alyan's request: where he is comes from the schedule. Don't reintroduce geolocation unasked. Watching Gammage by hand uses a flat 10 min walk (`stopWalkMinutes`).
- **The map.** `components/ShuttleMap.tsx`. The bus is a small 3D model (`components/bus3d.ts`, three.js, built from boxes so there's no file to download; colours from `--bus-blue` / `--bus-orange`). It is drawn on **its own transparent canvas over the map**, not in the map's WebGL context: sharing the context left MapLibre's street layers blank, and meant redrawing the whole map for every frame of the drive. A do-nothing custom layer hands over the camera matrix each time the map draws. If three.js or a second WebGL context isn't available, the old flat SVG marker stays. The map is pitched (38° overview, 58° following) with 3D buildings from the base tiles, and `tint()` repaints the base style in the app's own colours (the stock dark style is too dark to see streets). Light and dark swap the base style and everything is redrawn in `decorate()`. `lib/trail.ts` keeps the last 650 m driven as a line that fades away behind the bus; the lit road ahead fades towards the stop. **Off its usual route, both lines turn violet** (`--detour`) and the lit road is the usual one from where the bus left it (`lastS`). `lib/motion.ts` moves the bus: each update it drives forward along the learned route to the new position at a steady speed over about one poll interval, turning with the road, and never reverses (a target slightly behind means hold; a big gap means jump). The road from the bus to the stop being waited at is lit orange. "Follow bus" zooms in and keeps it centred. Off the route it slides straight to the reported spot.
- **Where the plan runs.** The tick builds it for alerts; the browser builds the same plan from `/api/shuttle`'s `private` payload so taps on Today show at once. Today's choices (skip, left early, class is out, on the bus, home, replan) live in `schedule.override` and expire with the date.
- **Private vs public.** The bus position is public, and a signed-out visitor sees it with a sign-in card below. Settings, schedule and plan come only with that person's session cookie. Nobody's schedule is ever in the repo: this repo is public.
- **Screens.** `/` Today (`Tracker.tsx`, `Timeline.tsx`), `/schedule` Classes (`ScheduleEditor.tsx`: each block opens in a sheet and saves on its own), `/settings` (`SettingsPage.tsx`: alerts, alert hours, walking, theme, account, delete account), `/privacy`. `components/Account.tsx` is the one place the session is known; `AppShell.tsx` is the tab bar. Theme is light, dark or the phone's, kept on the device (`lib/theme.ts`) and set on `<html>` before first paint.
- Hosted: Next on Vercel, Supabase holds `shuttle_kv` and `shuttle_users`, and pg_cron calls `/api/tick` every 30s (`db/schema.sql`). The app reaches the tables with the publishable key plus a private header, not a secret key. Vercel Hobby cron is daily only, so it can't drive this. Locally, state is in `.data/`.

## What the bus actually does (measured 2026-11-06, Friday evening)

- One loop takes about 35 min and covers 9.2 km: SoL → University west → McClintock south → Apache west → Forest north (the Gammage stop) → turnaround → Forest south → Apache east → McClintock north → University east → around the back of SoL.
- The driver sometimes takes other streets. Seen so far: out via University → Rural → Apache (2026-11-06), and back from campus straight along University Dr to McClintock (2026-11-16). `roughEtas` in `lib/track.ts` still gives a time then: the next stop is whichever follows the last place on the loop, timed by road distance at 1.25× the usual pace, flagged `rough` so the screen says "roughly" and the planner adds 3 min of doubt. Scored on the two recorded detours: within about half a minute on the University Dr return, and about 3.5 min early on the Rural one (early is the safe side for catching it). "Off route" with no time is for a bus more than 500 m outside the loop's area, or one within 800 m of its next stop and driving away from it (seen 2026-11-16: it left SoL eastward for a break, parked 800 m away from 1:19 to 1:33 PM, and came back).
- The University Dr return is common: 2 of the 3 returns recorded on Monday 2026-11-16 used it. The rough time on it was typically 22 s off across 100 positions, about as good as the learned loop, so it has not been learned as a second path. The tick still logs where the bus goes off the loop (`DayLog.detour`, a week kept) in case a detour turns up that the rough time handles badly.
- Where that detour rejoins the loop (University at McClintock) both directions of the route are within reach. Waiting at the red light there, the bus was once placed on the outbound side and shown 23 min from SoL when it was 2 min away. That is what `Course` fixes.
- **Late afternoon it turns round short of Gammage.** On Monday 2026-11-16 the 4:00, 4:37 and 5:26 PM loops stopped on Forest at 33.4161, -111.9366 (about 110 m before the learned stop), then went east and south back to Apache without going up to the usual spot. Earlier loops that day went all the way. Why isn't known (one day seen; possibly a closure further up Forest). The Gammage stop has `leadM: 150` in `route-data/stops.json` so a bus waiting at that corner reads as "Bus is here" and is logged as a visit. The turn-round itself is off the loop for about 30 s and shows no time, because the bus is driving away from the stop it was due at. Ask Alyan where it actually picks up at that hour before changing more.
- **It takes breaks off the loop.** Same day, twice (12:58 to 1:40 PM and 4:47 to 5:13 PM): about 20 min at SoL, then parked on University about 800 m east of SoL (33.4224, -111.8943), then back to SoL. That makes a gap of about 40 min with no bus, which the planner can't foresee from the loop length.
- To score a change, replay a recorded trail through `buildSnapshot`, carrying `prevS` and `course` from one position to the next, and compare the times with when the bus really reached each stop.
- The loop has slack and the driver spends it in different places: 20s to 5 min at Gammage, 1 to 5 min at the Apache/McClintock light, 3 to 11 min at SoL. That's the limit on ETA accuracy, and why an ETA can drop by minutes at once. Don't treat the leave alert as a moment; it's a threshold.
- The bus waits at SoL for minutes, in up to three spots: the east driveway, the back of the property, and the University Dr curb. Which one riders board at isn't known yet, so the SoL stop starts at the driveway and `holdM` keeps "Bus is here" on until it leaves the curb. `canCatch` counts the wait.

## A full weekday (logged Thursday 2026-11-12)

- First movement 6:59 AM, left SoL 7:02 AM, at Gammage 7:14. Last loop back at SoL 7:07 PM. Ends seen so far: Mon 7:01 PM, Tue 6:59 PM, Thu 7:07 PM, Fri 7:05 PM.
- 22 loops in the day. The gap between buses at a stop was typically 31 min (20 to 45), shorter than the 35 min learned from Friday evening, and it drifts: there is no fixed clock timetable. `typicalLoop` measures it from the log and the planner uses that once there are enough buses.
- Wednesday 2026-11-11 (Veterans Day) had no movement at all, with every check running. Holidays look like "no service" days in the history.
- The last loop of the day waited at Gammage from 6:28 to 6:54 PM.
- **Timing is corrected for the feed's delay.** A position is 5 to 20 seconds old when used. `ageCorrection` takes that off the arrival times of a moving bus, and the log stamps events with the position's own time, not the time of the check.

## Rules

- Never commit anyone's class schedule or personal times. The repo is public; they belong in that person's row. (`lib/buildings.json` is ASU's public list of every Tempe building and is fine.)
- Never return or log what an alert says, or anyone's schedule, from the tick: pg_net keeps the replies for a while, and alert text names people's classes. The tick reports alert kinds and a head count only.
- Don't add analytics, tracking or location. The privacy page (`app/privacy/page.tsx`) promises there is none; if what's collected, where it's hosted or who it's shared with ever changes, that page and `app/terms/page.tsx` change in the same commit, with their dates. Both are linked from the home page for everyone and are the links given to Google: https://solshuttle.app/privacy and https://solshuttle.app/terms.
- Never put the Samsara share token in a tracked file. Scripts read it from `.env.local`.
- A plan time is only as good as its source. Keep `source` and `plusMinus` honest, pick the earlier bus when unsure, and say "no time yet" rather than guess hours ahead.
- Never request the driver's name or any driver field. Position fields only.
- Never poll Samsara faster than its own page does (about every 14s). Keep the cache.
- Never show a time from stale data. If `status` isn't `live`, the answer has no minutes in it.
- Don't show Samsara's `formatted` address to the user: it's often a block or two wrong. Describe position by the next stop.
- The feed is an undocumented internal endpoint. It can change or stop without warning, and the share link can be revoked. When it does, the app should say "No signal", not crash.

## Gotchas

- Service ends around 7 PM on weekdays and there was no movement on the one weekend watched. The planner turns a ride with no bus into a walk, with the reason.
- **Never draw three.js into MapLibre's own WebGL context here.** With three 0.187 and MapLibre 6.16 the custom layer rendered the bus and left every base-map layer blank (tiles loaded, nothing drawn), in both themes. The bus has its own canvas instead; see the map bullet.
- To change a value that already exists on Vercel, pipe it into `vercel env add NAME production --force`. `vercel env rm ... --yes` asks for approval and does nothing when run without a terminal, so remove-then-add silently leaves the old value in place.
- The Bash tool mangles heredocs and `node -e` strings that contain backticks or mixed quotes. Write a patch script to the scratchpad with the Write tool and run that.
- `next/font` fetches Bricolage Grotesque at build time. A build with no network fails on it.
- Walking SoL to campus is about 45 min (3.2 km as the crow flies, more by street), not a quick hop.
- The planner can't see where anyone is. A bus is taken as caught once its leave time passes; "Missed it, plan again" is how they correct it. iOS gives a PWA no background location, no step count and no buttons on notifications.
- Git Bash's `TZ=America/Phoenix date` prints UTC here. Get Tempe time from node (`Date.now() - 7h`) instead.
- MapLibre 6 can't find its worker under Turbopack. `public/maplibre-gl-worker.mjs` is copied by postinstall and set with `setWorkerUrl`. It's gitignored, so a fresh clone needs `npm install`.
- MapLibre can't parse `oklch()`, so `cssColor()` in `ShuttleMap.tsx` converts tokens through a canvas.
- `web-push` and `maplibre-gl` have no default export in these versions.
- iOS web push only works from the Home Screen app, needs HTTPS, and every push must show a notification.
- In an iPhone Safari tab (not the Home Screen app) there is no Push API: a service worker registration exists but `registration.pushManager` is undefined, and `PushManager` is not on `window`. Reaching through it once crashed the settings load, so the phone showed only the map with no passcode box. All push lookups go through `lib/push-client.ts`, which answers "no subscription" instead. Test by deleting `pushManager` from `ServiceWorkerRegistration.prototype` in a desktop browser.
- A hidden browser tab or pane pauses `requestAnimationFrame` and the visibility-gated polling, so the bus looks frozen there. To measure motion in a hidden pane, stand in a `setTimeout` for rAF and force `document.visibilityState` to `visible`.
- The map takes two fingers to move on touch screens (`cooperativeGestures`), so one finger scrolls the page past it.
- Samsara sends no pings while the bus is parked (gaps over 4 min). Pause lengths run to the next moving ping, and `feedStatus` keeps a parked bus live for 6 min. It sends a heartbeat every 5 min while parked, so a bus that's done for the day still reads as `live`; `parkedUp` (20 min, from `lastMovedAt`, which only the tick updates) is what turns that into "Not running".
- Adding a file to `public/` while `next dev` runs can 404 until the next reload.
